# Contributing

Thanks for your interest in contributing to Spreadsheet Schema Manager.

## How to contribute

- Open an issue to discuss a proposed change before starting larger work.
- For bug fixes or feature work, create a branch from the main branch.
- Keep changes focused and scoped to a single problem where possible.
- Update any relevant documentation and deployment notes when behaviour or configuration changes.

## Pull request process

1. Create a branch from the default branch.
2. Make the change and include focused tests where practical.
3. Run the relevant test or validation command before submitting.
4. Open a pull request with a clear summary of the change and why it is needed.
5. Ensure the README or deployment docs are updated when configuration, environment variables, or infrastructure behaviour changes.
6. Await review and address feedback from maintainers.

## Coding expectations

- Keep the code readable and consistent with the surrounding project style.
- Prefer small, well-tested changes over broad refactors.
- Include tests for bug fixes and new functionality where feasible.
- Preserve backwards compatibility unless the change explicitly requires a breaking update.

## Community expectations

We expect contributors to be respectful, constructive, and professional in discussions, reviews, and issue comments.

Please also review our [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) and [SECURITY.md](SECURITY.md) for project-wide expectations and reporting procedures.
